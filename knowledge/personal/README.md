
# personal/

## 目录定位

`personal/` 用于存放个人经验、踩坑记录、临时理解和碎片素材。这里的内容是入库前的原始素材，不等同于正式知识。

个人内容必须先按所有者建立 `personal/<ownerCode>/` 边界。ownerCode 是当前仓库内唯一且长期不变的小写 kebab-case 标识；姓名、昵称或团队称呼只记录在所有者 README 中，不作为需要随显示名称变化的目录名。

ownerCode 应使用仓库内分配的稳定标识，必要时增加稳定后缀解决冲突。不要把邮箱、手机号、工号等敏感或组织绑定信息直接作为目录名。

这里的所有者边界只表达内容来源和检索路由，不提供权限或隐私隔离。personal 内容仍会进入共享 Git 仓库，并可能被自动化工具读取或索引；不得存放密码、Token、私密通信、个人隐私或其他不应进入仓库的信息，真正私密内容必须留在仓库外。

## 应包含的内容

- 个人研发经验、踩坑记录与临时理解。
- 尚未结构化、需要沉淀的原始经验素材与碎片笔记。

## 不应包含的内容

- 已经整理确认、可作为团队结论的知识：应先进入 `candidate/`，再进入 `main/` 或 `applications/`。
- 跨应用统一、需要全员遵守的正式规则：不放入本目录。

## 维护规则

- 个人笔记可以作为知识入库素材，但不能直接代表项目正式结论。
- 只有产生真实个人内容时才从 `template/personal/{ownerCode}/` 建立所有者目录；不得为了登记人员预造空目录。
- 每个所有者目录及其主题子目录必须包含 README 与 INDEX，并至少存在一份非导航的个人 Markdown 内容。
- personal 第一版不强制建立 `main/`、`applications/` 等镜像；形成明确候选结论后，再进入 candidate 的目标镜像。
- 多次验证或需要复用的内容，先整理到 `candidate/`。
- 经确认后，再进入 `main/` 或 `applications/`。
- 已退出个人有效经验路径但仍需追溯的内容，按原相对路径移动到 `archive/personal/<ownerCode>/`。
