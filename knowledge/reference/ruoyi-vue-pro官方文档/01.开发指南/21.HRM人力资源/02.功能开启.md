进度说明：

- 管理后台，请使用 [https://gitee.com/yudaocode/yudao-ui-admin-vue3](https://gitee.com/yudaocode/yudao-ui-admin-vue3) 仓库的 `master` 分支
- 后端项目，请使用 [https://gitee.com/zhijiantianya/ruoyi-vue-pro](https://gitee.com/zhijiantianya/ruoyi-vue-pro) 仓库的 `master`（JDK8）、`master-jdk17`（JDK17/21）或 `master-jdk25`（JDK25）分支

HRM 系统，后端由 `yudao-module-hrm` 模块实现，前端由 `yudao-ui-admin-vue3` 的 `hrm` 目录实现。

考虑到编译速度，默认 `yudao-module-hrm` 模块是关闭的，需要手动开启。步骤如下：

- 第一步，开启 `yudao-module-hrm` 模块
- 第二步，导入 HRM 系统的 SQL 数据库脚本
- 第三步，重启后端项目，确认功能是否生效

补充说明：

由于 HRM 请假使用到 BPM 的审批功能，所以你需要先看 [《工作流》](https://doc.iocoder.cn/bpm/) 文档，将工作流开启！

## 4. 全局说明

① HRM 的**基础数据来自 System 模块**：部门复用 `system_dept`，后台账号复用 `system_users`。建议先完成组织与员工档案，再配置考勤、社保、薪资和绩效，避免月度计算缺少员工基础资料。

② HRM 区分**管理端**与**员工端**两套菜单，但共用同一个后台账号体系。SQL 导入后，需要为 HR、主管和员工角色分别分配菜单；员工端还要先在员工档案中把 `hrm_employee.user_id` 绑定到 `system_users.id`。未绑定员工档案的账号只会看到开通引导，详见 [《【组织】工作台、组织架构》](https://doc.iocoder.cn/hrm/organization/)。

③ **请假审批复用 BPM**：员工请假的流程定义 Key 固定为 `hrm_attendance_leave`，审批完成后由 HrmAttendanceLeaveStatusListener 回写请假状态，详见 [《【考勤】考勤管理》](https://doc.iocoder.cn/hrm/attendance/)。

④ **预约生效依赖定时任务**：在 [基础设施 -> 定时任务] 中配置 HrmEmployeeChangeJob、HrmSalaryChangeJob 和 HrmPerformanceAppealTimeoutJob，分别处理到期的人事异动与离职、到期的调薪，以及超时的绩效申诉节点。未配置时，预约生效的记录会一直停留在待生效状态。（如果是微服务版本，需要去 XXL-Job 里去配置）
