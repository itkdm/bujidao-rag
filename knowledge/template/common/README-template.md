# {目录名称}

> 本文件是某个 Knowledge 受管理目录的 `README.md`。
> 职责边界一句话：**README = 这个目录应该是什么**（稳定职责与维护契约）。
> 不要在此维护动态文件清单、内容索引或任务路由，这些由 `INDEX.md` / `ROUTING.md` / 具体知识文件承担。

## 目录定位

说明当前目录在 Knowledge 体系中的职责，以及主要解决什么问题。

填写要点：

- 一句话说清这个目录是「什么层 / 什么范围 / 解决什么」。
- 只描述稳定职责，不罗列当前具体内容。
- 不要把应用实际业务信息（技术栈、核心模块、业务目标等）复制进来。

## 应包含的内容

说明哪些内容应该放入当前目录。

填写要点：

- 用稳定的「内容类别 / 职责范围」描述，而不是当前文件清单。
- 列出本目录正常接纳的知识类型。

## 不应包含的内容

说明哪些内容不属于当前目录。

填写要点：

- 指出越界内容通常应放到哪个同级或上层目录。
- 必要时简短指出目标目录名，但不写路径细节或文件清单。

## 维护规则

说明新增、修改、删除、使用当前目录内容时需要遵守的局部规则。

填写要点：

- 只写当前目录自己的规则，不复制全局规则。
- 例如：只记录已确认的事实、不把规划当现实、变更后需重新核对来源等。

## 补充说明

可选。

只有存在无法通过前四节表达、且确实需要长期保留的特殊说明时才使用。

没有内容时整个章节省略。

## 使用约束（模板说明，不写入实际 README）

- README 应尽量稳定，新增一个普通知识文件不应导致 README 必须修改。
- 禁止在 README 中维护：当前具体文件、文件数量、动态知识清单、完整内容索引、详细任务路由、具体 Agent 读取链、当前业务实现摘要、某应用临时状态、模板使用说明、全局 Metadata 规范重复内容。
- 上述禁止内容分别由 `INDEX.md` / `ROUTING.md` / 具体知识文件 / `KNOWLEDGE-METADATA-RULES.md` 承担。
