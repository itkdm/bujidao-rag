# tech/

## 本目录负责什么

`tech/` 回答：**在当前应用和技术栈中应该怎么实现？**

沉淀技术实现约束，核心表达 **How we implement it**。

## 什么内容应该放这里

- 架构约束
- 模块边界
- 框架用法
- Controller / Service 等工程约定
- 事务、缓存、MQ、异常处理、安全实现
- 测试等技术知识

## 什么内容不应该放这里，以及应该去哪里

- 模块、API、表、配置等事实入口 → `base/`
- 业务规则、权限、状态约束 → `rule/`
- 功能能力与业务流程 → `feature/`
- 具体业务角色与产品权限矩阵 → `rule/` 或正式产品文档

## 新增本类知识时需要遵守的最基本归属原则

只描述实现方式与技术约束；不定义业务规则，不记录事实入口，不解释业务流程。
