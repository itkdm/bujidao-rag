# 知识库玩法引导

## 定位

这是本知识库体系的官方入门引导 Skill。它帮助首次接触体系的用户理解目录、路由、研发文档、项目级 Skill、验证工具和人工决策之间的关系。它不是初始化 Skill、日常开发 Skill 或文档维护 Skill，也不是业务实现 Skill。

默认行为是讲解和展示逻辑，不创建分支、不修改代码、不新增 Change、不推送 Git。只有用户明确要求“按示例实际演示”时，才可把讲解转为一次独立的实操任务，并完成一次明确交接：列出基线分支、拟用演示分支、允许修改的精确路径、是否允许创建 Change、验证范围、清理方式和是否允许提交/推送。交接未确认前保持只讲解模式。

## 讲解前提

说明目标项目已经完成初始化，并指出应先查看根 `AGENTS.md`、`knowledge/README.md` 和 `knowledge/ROUTING.md`。最小判定清单是：三个入口文件存在且可读、ROUTING 能指向实际目录、目标项目级 Skill 目录可被发现、知识库校验入口（若项目提供）可定位。任一项缺失或矛盾，只解释缺少哪些前提，不尝试代替初始化流程。

不要把当前示例项目的应用名、技术栈、模块状态或业务结论当成用户项目事实。示例中的 RAG、芋道或其他模块名称只能作为说明流程的占位案例。

## 推荐讲解主线

用一个假设的低风险小任务串起完整流程，例如“在临时分支修复一个可复现的边界 Bug”。不要求真的实施，只需逐阶段说明会发生什么、产出什么、谁负责判断。

### 1. 任务与隔离

先确认任务属于代码研发、知识维护、调研还是初始化。若实际执行，才创建带演示标识的临时分支，并先记录基线、HEAD 和工作区状态；已有未提交修改必须受到保护。工作区干净时可以按交接协议继续；工作区不干净时默认只做只读讲解，若要实操必须先展示修改清单并获得用户确认，无法区分归属时停止实操。

人工判断：任务范围、风险、是否需要真实修改、是否允许产生或保留演示产物。

程序可执行：读取 Git 状态、创建分支、检查工作区。

### 2. Skill 与知识路由

解释“Skill 负责行动方式，knowledge 负责长期上下文，docs 负责一次变更的过程记录”。根据任务类型选择相应项目级 Skill；随后先读 `knowledge/README.md`，再读 `knowledge/ROUTING.md`，只加载任务需要的最小知识。涉及 Change 时再读 `docs/changes/README.md` 和对应模板，涉及事故时按需读 `docs/postmortem/README.md`。

人工判断：选择哪个 Skill、读取哪些知识、哪些内容是当前项目事实、哪些只是候选或参考。

程序可执行：按路径读取文件、检查链接、扫描目录和索引。

### 3. 方案、实现与文档

解释何时需要 Change：改变行为、契约、架构，或未来必须知道“为什么”时创建；简单的无行为文字修正通常不需要。未确认但可能长期复用的结论进入 `knowledge/candidate/`，不能直接成为正式事实。

人工判断：是否创建 Change、选择类型、范围边界、方案取舍、验收条件，以及候选内容是否值得长期保留。

程序可执行：运行目标项目实际存在且由其根级规范指定的测试、构建、格式检查和知识库校验；`python knowledge/scripts/validate.py`、`git diff --check` 仅是本仓库示例。命令不存在或无法执行时如实报告，不得假设成功。

### 4. 完成、审查与生命周期

解释实现完成后需要检查代码、验收证据、文档链接和正文语义；满足条件后才把 Change 从 `proposed/` 移到 `implemented/`。修改代码、knowledge、docs 或 Skill 后，应安排独立子 Agent 审查，并由人决定是否采纳意见。

人工判断：是否完成、是否存在未决风险、是否晋升候选知识、是否需要 Postmortem、是否接受审查建议。

程序可执行：执行目标项目实际存在且由其根级规范指定的验证命令；本仓库示例包括 `python knowledge/scripts/validate.py`、`git diff --check` 和项目测试。校验器只能验证结构、链接和可执行检查项；命令不存在或无法执行时如实报告，不得假设成功。

### 5. 复盘与清理

讲解最终报告应区分：项目原有事实、演示假设、实际产物、人工判断、自动验证和未解决问题。若实际演示，清理前列出精确的临时分支和文件路径，切回基线后再删除；默认不提交、推送或合并。

人工判断：哪些成果值得保留、是否迁移到正式分支、是否可以安全删除。

程序可执行：展示状态、列出文件、执行经过确认的删除操作；不得使用未解析的宽泛通配路径。

## 讲解输出格式

使用中文，按“阶段 → 目的 → 人工判断 → 程序执行 → 可能产物 → 常见误区”说明。明确强调：

- 这套体系是模板和方法，不预设行业、产品或具体业务；
- Skill 不等于自动决策，知识库也不等于当前代码事实；
- 自动校验通过不代表业务正确；
- 演示示例不应自动写入正式 knowledge 或 docs；
- 只有用户明确授权，才从讲解切换到实际操作。
